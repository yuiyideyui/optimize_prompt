# ComfyUI-Comic2Anime 补充开发需求：QwenEdit 参考图传入 + Gemini 提示词生成 + Gemini 结果质检闭环

> 本文是对《ComfyUI-Comic2Anime：完整漫画转动漫系统升级改造开发需求》的**强制补充**。请与主文档一起交给编码 AI。  
> 重点是确保现有 Qwen-Image-Edit 2511 自定义节点真的收到参考图片，并且整个素材生成流程由 Gemini 生成提示词、QwenEdit 生成图片、Gemini 评估结果，再根据评估结果迭代修正。  
> **先检查仓库中的真实节点代码和 Gemini 调用方式，再实现。** 下文不授权编码 AI 虚构节点端口、模型参数或 API。

---

## 1. 必须实现的完整闭环

```text
漫画与知识库中确定的素材需求
    ↓
构建结构化 Asset Request
    ↓
查询资产库，选择已审核的参考图
    ↓
校验参考图用途、人物/形态/状态匹配与节点输入数量限制
    ↓
Gemini 生成 Qwen-Image-Edit 2511 专用编辑提示词
    ↓
组装 QwenEdit 输入：提示词 + 实际 IMAGE 参考图 + 已确认的节点参数
    ↓
执行现有 QwenEdit 自定义节点
    ↓
得到生成图片 IMAGE
    ↓
把生成图片和原始任务要求发送给支持视觉输入的 Gemini 模型进行质检
    ↓
解析结构化质检结果
    ├─ PASS：登记为候选素材，保留所有生成与审核记录
    ├─ RETRY：根据具体失败项修改提示词/参考图选择，再生成
    └─ NEEDS_HUMAN_REVIEW：存在重大歧义或达到重试上限，等待人工处理
```

**不能省略任何关键步骤：**

- 不能只从资产库查询图片路径，却没有把图像转成/传成 Qwen 节点需要的 `IMAGE` 输入。
- 不能只让 Gemini 写提示词，却没有让 Gemini 看生成结果并判断是否符合要求。
- 不能把“API 调用成功”当成“图片合格”。
- 不能把 Gemini 的质检结论直接写回人物标准设定，或把未经审核的生成图设成正式主参考图。
- 不能无限自动重试。

## 2. 第一步：建立结构化素材任务

在调用 Gemini 前，必须先生成可保存的 `ASSET_REQUEST`。它应来自完整漫画分析、当前人物/地点状态和用户要生成的资产类型，而不是只传一句“生成一个动漫人物”。

建议字段（按当前项目数据结构适配，不要求机械复制名称）：

```json
{
  "request_id": "stable_request_id",
  "project_id": "project_id",
  "asset_type": "character_outfit_reference",
  "target_entity": {
    "entity_type": "character",
    "entity_id": "character_id"
  },
  "appearance_version_id": "appearance_id",
  "outfit_id": "outfit_id",
  "persistent_state_ids": [],
  "expression_or_pose": null,
  "location_state_id": null,
  "purpose": "为后续漫画转动漫镜头提供经过审核的角色服装参考",
  "must_preserve": [
    "人物身份特征",
    "脸部结构",
    "基础发色与瞳色"
  ],
  "allowed_changes": [
    "仅按当前任务要求调整的服装或姿态"
  ],
  "must_not_change": [
    "不得擅自改变人物身份",
    "不得添加漫画没有依据的伤疤或配饰"
  ],
  "source_evidence": [],
  "reference_asset_ids": [],
  "validation_warnings": []
}
```

上述是结构示例。正式运行时所有 ID 必须来自数据库；如果缺少关键字段，应该提示补充或标记待确认，不能把示例占位值传入模型。

### 2.1 任务必须区分目标资产类型

至少识别这些类型，避免用同一种提示词模板生成所有素材：

- 人物身份基准图/三视图。
- 指定服装的角色设定图。
- 脸部细节/表情参考图。
- 持续性状态图（受伤、淋雨、衣服破损等）。
- 场景环境图。
- 人物与背景合成参考图。
- 道具/配饰参考图。

每种任务有不同的保留规则、允许修改内容和质检标准。

## 3. 第二步：参考图必须真正传给 QwenEdit

### 3.1 参考图选择与用途

根据素材任务，从资产库选择参考图，并为每张图记录：

- `asset_id` 和可加载的实际文件路径/资产 URI。
- 资产用途，例如 `character_identity`、`face_detail`、`outfit`、`state_reference`、`scene_reference`、`composition_reference`。
- 对应人物、外观版本、服装、状态或地点 ID。
- 审核状态、版本和哈希。
- 被选中的理由，以及可能存在的冲突。
- 在 QwenEdit 实际节点中将被连接到哪个参考图输入端口。

只选择审核通过且与当前任务兼容的参考图，除非用户明确允许使用候选图。

### 3.2 真实 IMAGE 数据流

实现时必须沿用当前 QwenEdit 自定义节点的真实接口。已知设计方向是一个必选参考图输入，并可能有最多两个可选参考图输入；编码 AI 必须检查当前代码确认端口名称、类型和数量，不可直接假设。

期望的数据链路：

```text
资产库查询（返回 asset_id）
    ↓
资产加载器（按 ID 读取文件并校验哈希）
    ↓
转换为 ComfyUI IMAGE 张量/批次（使用项目现有图像加载约定）
    ↓
连接 QwenEdit 的真实参考图输入端口
    ↓
QwenEdit + Gemini 生成的提示词
    ↓
输出 IMAGE
```

关键验收点：

1. 参考图必须从真实图片文件加载成当前节点需要的图像数据类型，而不只是把文件路径或资产 ID 当成图片输入。
2. 所选参考图必须按确定顺序连接到节点的真实输入端口。
3. 每个端口的参考用途必须写入生成运行记录。
4. 超过节点上限时，先依据任务优先级选图，不能静默丢弃；如果缺失的参考会导致结果不可靠，应提示无法满足或要求用户确认。
5. 如果现有节点只接受有限数量的图，不要假装能一次输入全部素材。可采用优先选择、分阶段制作或经过审核的合成参考图策略。
6. 输出的 `IMAGE` 应继续传给资产登记节点；登记节点保存图片并记录它实际使用的参考资产 ID。
7. 对每次运行保存输入图片 ID、版本、哈希和端口映射，确保结果可追溯。
8. 不得改变现有 QwenEdit 节点的核心推理逻辑，除非实际检查后发现有必要的兼容性修复；资产加载、参考图选择和生成记录尽量放在独立节点中。

### 3.3 参考图冲突检查

在调用模型之前检查：

- 任务要求冬装，参考图却是夏装。
- 任务要求右脸受伤，参考图显示左脸受伤或没有伤口。
- 参考图来自不同人物或不同年龄阶段。
- 场景参考的时间/天气与任务冲突。
- 两张参考图对发色、衣服、配饰或脸部特征给出互相矛盾的信息。
- 资产是候选/拒绝状态，却被当作正式参考图。
- 当前节点输入数量不足以表达所有硬性约束。

对硬性冲突不能只在日志中警告后照常生成；应重新选图、请求确认，或明确将该约束标为未解决。

## 4. 第三步：Gemini 生成 QwenEdit 专用提示词

Gemini 的职责是把结构化任务和参考图用途转换成清楚、可执行的图像编辑提示词。提示词必须明确：

1. 目标是什么、要生成哪种资产。
2. 每张参考图分别用于什么。
3. 哪些特征必须保留。
4. 哪些内容允许改变。
5. 哪些内容禁止改变。
6. 角色身份、服装、状态和场景之间的优先级。
7. 输出构图、视角、画风和画面要求。
8. 不确定的设定不能自行补充。

Gemini 输入至少应包括：

- 结构化 `ASSET_REQUEST`。
- 相关漫画原始证据和已确认知识。
- 已选参考图的用途说明与 ID。
- 参考图的视觉内容（在接口和预算允许时提供图像输入），而不只是路径字符串。
- 当前 QwenEdit 节点真实支持的输入能力和限制。
- 当前任务的提示词版本和可修改字段。

Gemini 输出必须结构化，建议包含：

```json
{
  "prompt_version": 1,
  "detailed_description": "可直接用于当前 QwenEdit 任务的编辑提示词",
  "reference_usage": [
    {
      "reference_asset_id": "actual_asset_id",
      "role": "character_identity",
      "instruction": "用于保持人物身份，不用其背景覆盖目标背景"
    }
  ],
  "must_preserve": [],
  "allowed_changes": [],
  "negative_constraints": [],
  "uncertainties": [],
  "validation_checklist": []
}
```

如果现有提示词规范采用其他字段名，应适配现有代码。不要为了使用上述示例而破坏现有接口。

### 4.1 提示词生成约束

- Gemini 只能基于任务和来源证据生成提示词，不可编造人物设定。
- 身份参考与场景参考的作用应明确分开，避免把身份参考图的背景/光照无条件复制到目标场景。
- 如果任务只要求换衣服，应明确保留人物脸部、发型、瞳色和其他身份特征。
- 如果任务只生成表情参考，不应顺便改变服装、年龄或人物设计。
- 如果源漫画无法确定某个特征，输出不确定项，不要自行创造固定设定。
- 记录原始提示词、Gemini 生成结果、模型标识（可获得时）、参数、时间和输入任务版本。
- 不要将 Gemini 生成提示词直接覆盖原漫画知识或人物标准描述。

## 5. 第四步：调用 QwenEdit 生成图片

执行前再次校验：

- 结构化素材任务完整。
- Gemini 提示词非空且与任务类型匹配。
- 参考图文件可加载、哈希正确、数量符合节点上限。
- 每个参考图用途与输入端口映射已确定。
- 硬性冲突已解决。
- 输出路径和运行 ID 已创建，且不会覆盖旧资产。

调用现有 QwenEdit 自定义节点时，使用它真实要求的提示词和 IMAGE 输入端口。保存本次运行的输入快照，至少包括：

- `request_id`。
- Gemini 提示词版本。
- 实际参考资产 ID/版本/哈希/端口。
- QwenEdit 节点及模型配置（实际可获取的部分）。
- 实际使用的参数和随机种子（若节点支持）。
- 运行状态、错误信息和输出图片。
- 生成时间和重试序号。

模型调用成功只代表得到输出，不代表素材通过质检。

## 6. 第五步：Gemini 必须检查生成结果

Gemini 质检不能只看生成提示词，也不能只读一段文字描述。必须把**实际生成图片**作为视觉输入，并同时提供原始素材任务、审核规则和所使用的参考图/关键证据。

如果当前 Gemini 接口支持图片输入，传入实际生成图片；根据任务需要，可同时传入原始漫画证据与参考图。若接口不支持图片输入或当前环境无法使用视觉能力，应明确失败，不可退化成“只凭提示词判断图片合格”。

### 6.1 质检检查项

根据资产类型启用对应检查项：

**人物身份**
- 是否为正确人物。
- 脸型、眼睛、瞳色、发色、发型和体型等关键特征是否保留。
- 是否误混入其他角色的特征。

**服装/配饰**
- 服装款式、颜色、图案、领口、袖口和关键配饰是否符合目标。
- 是否误用其他服装版本。
- 只要求修改服装时，人物身份是否发生非预期改变。

**脸部/表情/身体状态**
- 表情是否符合要求。
- 伤口在左右侧、形状和位置上是否正确。
- 淋雨、湿发、泪痕、污渍、衣物破损等状态是否与任务一致。
- 是否把临时表情错误地固化成角色永久设定。

**场景/构图**
- 场景、时间、天气和光照是否符合要求。
- 目标画面是否按要求保留人物和环境关系。
- 合成图是否存在明显边缘问题、比例错误或空间冲突。

**画风/图像质量**
- 是否符合目标的日本传统 2D 动漫视觉要求。
- 是否有明显变形、重复部件、异常文字、结构错误或严重伪影。
- 不把轻微细节差异一概判为失败；应根据用途和严重程度判断。

### 6.2 Gemini 质检结果必须结构化

建议返回以下字段：

```json
{
  "decision": "PASS",
  "overall_score": 0.0,
  "checks": [
    {
      "category": "character_identity",
      "result": "PASS",
      "severity": "none",
      "evidence": "对实际生成图片中可见特征的具体说明"
    }
  ],
  "failures": [],
  "uncertainties": [],
  "prompt_revision_instructions": [],
  "reference_revision_instructions": [],
  "human_review_required": false
}
```

`overall_score` 仅为示例字段；阈值必须在代码中明确配置，不能假设 0.0 就是有效分数。必须校验 Gemini 返回的 JSON/结构，处理空响应、无效值、模型拒答、网络错误和解析失败。

`decision` 至少区分：

- `PASS`：所有硬性约束通过，且质量达到设定门槛。
- `RETRY`：存在可通过修改提示词或参考图修正的问题。
- `NEEDS_HUMAN_REVIEW`：源设定有歧义、评估信心不足、硬性冲突无法自动解决或达到重试上限。
- `ERROR`：质检调用或输出解析失败。不能把 ERROR 当作 PASS。

模型的评分和结论必须配有具体证据；不能只输出“符合要求”或“看起来不错”。

## 7. 第六步：失败后由 Gemini 定向优化，再生成

流程必须形成有上限、可追踪的迭代：

```text
Gemini 初次生成提示词
    ↓
QwenEdit 生成图片
    ↓
Gemini 视觉质检
    ├─ PASS → 登记候选素材并结束自动循环
    ├─ RETRY → 根据失败项修订提示词/参考图 → QwenEdit 重生成
    ├─ NEEDS_HUMAN_REVIEW → 停止自动生成并等待人工处理
    └─ ERROR → 按错误策略重试质检或停止
```

### 7.1 优化范围必须受控

- 如果问题只是提示词表达不清，Gemini 只修订对应的提示词字段，例如 `detailed_description`，不要重写整个任务、原漫画证据或人物标准设定。
- 如果问题是参考图选错，应先修正参考图选择，再生成；不要企图只靠增加文字来抵消错误参考图。
- 如果问题是源漫画本身存在歧义，应转为人工确认，不能让 Gemini 无限猜测。
- 每轮都保存修改前后的提示词、质检报告、参考图变化和结果图。
- 每轮质检必须针对最新的实际输出图片，不能复用上一轮结果。
- 达到配置的最大生成重试次数后停止自动循环，输出失败报告和人工处理建议。
- 质检 API 暂时失败时，不得将素材自动标为通过。

建议将最大自动重试次数设为可配置项，并设置合理的默认值（例如 3 次）；不得无限循环。

### 7.2 不允许的错误做法

- 只调用 Gemini 一次生成提示词，之后不做质检。
- 让 Gemini 只看提示词而不看输出图片，却声称完成视觉检查。
- 每轮都完全重写全部提示词，导致要求漂移。
- 让质检模型直接修改角色身份、原漫画事实或审核通过的标准资产。
- 生成图片后直接标记 `approved`，跳过资产审核状态。
- 失败时自动重复整个章节/整部漫画的分析。
- 不保存每轮输出和参数，只保留最后一张图片，导致无法定位问题。

## 8. 节点职责与数据契约

按现有代码复用或扩展，不要求照搬名称：

1. **Asset Request Builder**：构建结构化素材任务。
2. **Asset Reference Selector**：选取参考资产并检查冲突。
3. **Asset Reference Loader**：将真实文件加载为 ComfyUI 所需的 IMAGE 数据。
4. **Gemini Asset Prompt Generator**：生成结构化 QwenEdit 编辑提示词。
5. **现有 QwenEdit 自定义节点**：接收提示词和真实参考 IMAGE，输出 IMAGE；优先保留现有推理逻辑。
6. **Gemini Asset Visual QC**：接收实际生成图和任务约束，输出结构化质检报告。
7. **Asset Prompt Revision Planner**：根据质检失败项决定修改提示词、换参考图或请求人工确认。
8. **Asset Registrar**：保存输出图片、哈希、运行记录、参考图关联与质检结果；默认状态为 `candidate`。
9. **Asset Review/Set Primary**：人工审核、批准、拒绝、设主参考和回滚。

如果现有节点已经承担其中某些职责，优先复用；但必须保证每一步的输入输出可检查、可保存，并能从 ComfyUI 工作流中实际连接运行。

## 9. 运行记录与资产状态

每次迭代至少记录：

- 素材任务 ID 与版本。
- Gemini 提示词生成请求/响应和模型标识（在可获取范围内）。
- 实际传给 QwenEdit 的提示词。
- 参考图 ID、版本、哈希、用途和端口映射。
- QwenEdit 运行结果、输出图片 ID/哈希和错误。
- Gemini 质检请求所使用的图片版本、质检报告和结论。
- 提示词修订前后差异、重试次数和每轮时间。
- 最终候选/审核状态及人工审核结果。

建议的状态流：

```text
REQUESTED
  → REFERENCES_READY
  → PROMPT_READY
  → GENERATING
  → QC_PENDING
  → PASS_CANDIDATE
     或 RETRY_PENDING
     或 NEEDS_HUMAN_REVIEW
     或 ERROR
```

状态名可适配现有数据库，但不能把生成、质检、审核合并成一个布尔值。

## 10. 必须进行的验收测试

### 测试 A：参考图真实传入

- 从资产库选一张人物身份参考图和一张目标服装参考图（如果节点真实接口支持）。
- 通过资产加载器加载成 IMAGE。
- 运行 QwenEdit。
- 验证节点实际输入端口收到图像数据，并保存对应的资产 ID/哈希/端口映射。
- 仅有路径或 ID、没有真实图像输入，判定失败。

### 测试 B：Gemini 提示词生成

- 输入明确的素材任务、漫画证据和参考图用途。
- 验证 Gemini 输出结构化提示词。
- 验证提示词明确写出必须保留与允许改变的特征。
- 验证任务缺少关键设定时会标记不确定，而不是编造事实。

### 测试 C：Gemini 视觉质检

- 将 QwenEdit 实际生成的图片传入 Gemini 视觉接口。
- 故意准备一个服装错误或人物特征错误的样例。
- 验证 Gemini 返回失败类别、具体证据和修订建议。
- 验证只提供文字、不传生成图片时不能报告视觉质检通过。

### 测试 D：定向重试

- 第一次生成的图故意不符合服装或脸部要求。
- Gemini 识别错误并输出定向修改建议。
- 第二次运行记录新提示词和实际参考图。
- 对最新生成图重新进行视觉质检。
- 达到最大重试次数后，任务停止并等待人工处理。

### 测试 E：候选资产与版本保护

- 质检通过的图片登记为候选素材（除非项目已有明确的自动批准策略）。
- 质检失败图片保留记录，但不得覆盖正式主参考图。
- 新版本与旧版本可追溯、可回滚。
- Gemini API 错误或质检结果无效时，素材不能自动变为通过。
